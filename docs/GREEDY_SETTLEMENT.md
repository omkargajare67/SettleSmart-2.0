# GREEDY SETTLEMENT RECOMMENDATION ALGORITHM

## 1. Overview
The Greedy Settlement Algorithm in SettleSmart 2.0 optimizes debt resolution across an organization's network of entities. Given a set of net financial balances, the algorithm computes an optimal, minimal set of bilateral settlement transfers required to neutralize all outstanding debts.

## 2. Mathematical Model
- **Balance Invariant**: Every transaction represents a zero-sum transfer of funds between two entities. Consequently, across all entities in an organization:
  $$\sum_{i=1}^{N} \text{balance}_i = 0$$
- If the sum of balances is non-zero, the system detects a balance anomaly and aborts calculation with error code `SETTLEMENT_ERR_UNBALANCED`.
- **Debtors**: Entities with $\text{balance} < 0$. They owe money to the network.
- **Creditors**: Entities with $\text{balance} > 0$. They are owed money by the network.
- **Settled Entities**: Entities with $\text{balance} = 0$. They require no transfers.

## 3. Algorithmic Procedure
1. **Extraction**: Query all active entity balances from the in-memory `HashMap` or database records.
2. **Partitioning**:
   - Extract all debtors into an array $D$. Store debt as positive magnitude $|\text{balance}_d|$.
   - Extract all creditors into an array $C$ with credit amount $\text{balance}_c$.
3. **Sorting / Ordering**:
   - Sort debtors in descending order of debt magnitude; break ties by debtor entity ID ascending.
   - Sort creditors in descending order of credit magnitude; break ties by creditor entity ID ascending.
4. **Greedy Matching**:
   - Iterate while there are remaining debtors and creditors:
     - Select the debtor $d$ with the largest remaining debt and creditor $c$ with the largest remaining credit.
     - Determine transfer amount: $T = \min(\text{debt}_d, \text{credit}_c)$.
     - Record recommendation: Debtor $d$ pays Creditor $c$ amount $T$.
     - Deduct $T$ from $d$'s remaining debt and $c$'s remaining credit.
     - If debtor $d$'s debt reaches 0, advance to the next debtor.
     - If creditor $c$'s credit reaches 0, advance to the next creditor.
5. **Complexity**:
   - Let $D$ be the number of debtors and $C$ be the number of creditors ($D + C \le N$).
   - Sorting takes $O(D \log D + C \log C)$ or $O(N^2)$ using in-memory sort.
   - The greedy matching loop terminates in at most $D + C - 1$ steps.
   - Total runtime is well within sub-millisecond execution bounds for hundreds of entities.

## 4. Deterministic Tie-Breaking
To guarantee idempotent recommendations across multiple calls, the algorithm enforces strict tie-breaking:
1. Primary criterion: Largest balance magnitude (paise).
2. Secondary criterion: Numerical Entity ID ascending.

## 5. Advisory Nature
- Recommendations generated by `GET /api/settlements/recommendations` are strictly **advisory**.
- SettleSmart never automatically executes or inserts transaction records for recommended settlements without explicit user initiation via the API.
